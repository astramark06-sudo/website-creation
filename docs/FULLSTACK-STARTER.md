# Local full-stack workspace

The Master Creator studio can export an original standalone Python/SQLite application using the project title and description. It supports adding, editing, completing, deleting, searching and filtering records. Extract the ZIP to a new folder and run `python server.py`. Open the printed loopback address. No external dependencies or paid service are needed. The application uses parameterized SQL, bounded input, same-origin request checks and a session token. Database persistence is local, not browser storage.

This is a single-user local starter, not an arbitrary backend generator or a production internet service. Do not expose it to the internet, tunnel its port, or store sensitive information. Public full-stack release requires independently implemented authentication, authorization, TLS, deployment configuration, backup and operational review. GitHub Pages cannot execute Python or host SQLite. The export does not publish anything.

CLI usage:

```sh
python scripts/creator_fullstack.py --title "My records" --description "Original workspace" --output workspace.zip
```

The regression tests validate ZIP content and database operations. A dedicated Chromium integration test exports the actual app from the studio, exercises create/edit/complete/filter/search/delete, checks unauthenticated requests are rejected, and restarts the local server against the same database. Verify the current CI result before claiming the browser test passed. Public deployment remains separate and unsupported.

## Typed data-model presets

Choose General records, Inventory, Issue tracking or Reading catalogue before exporting. Inventory adds quantity and storage location; Issue tracking adds priority and category; Reading catalogue adds pages and format. The generated form and list are driven by bounded model fields in config.json. Integers are validated as integers from 0 to 1,000,000; text is bounded; choices must match the configured options. The database stores model fields as structured JSON alongside existing records and rejects mismatched model definitions. Search includes field values. Existing general-record databases remain compatible. Use a new export folder and database for a different model. No arbitrary SQL, multi-user authentication, external data or production hosting is provided.

CLI: `python scripts/creator_fullstack.py --title "Inventory" --description "Local supplies" --model inventory --output inventory.zip`.

## Custom fields and linked records

Choose **Custom fields** in the studio and enter one field per line, such as `Quantity | integer`, `Location | text`, `Priority | choice | Low, Normal, High`, or `Related item | link`. Custom applications support 1 to 8 fields. Field identifiers are generated by the studio and the exporter validates every definition again. A link points to another record in the same local database; self-links are rejected and deleting a target clears the link. Search includes linked record titles. This is a bounded local relationship feature, not a general relational schema designer.

For the CLI, create a JSON array of field definitions and pass `--model custom --schema schema.json`. The schema file is limited to 32 KiB. A database is permanently associated with the exact field schema stored when it is created; changing config.json later causes the server to reject the mismatch instead of silently reinterpreting data.

Custom fields do not add accounts, network APIs, arbitrary SQL, executable expressions, uploads, secrets or public hosting. Use separate application architecture and review for those requirements.

## Local backup and recovery

From an extracted workspace, stop the local server, then run `python server.py --backup snapshot.sqlite3`. The command uses SQLite's consistent snapshot API, checks the configured model and database integrity, verifies foreign keys, and refuses to overwrite an existing file. Keep the matching config.json and generated application files with your backup. Backups contain all local records, so store them privately and do not commit them to GitHub.

To recover, use a **new** folder with the same exported application and matching config.json. Copy your trusted backup into that folder as workspace.sqlite3, then start the local server and inspect the recovered records and links. Keep the original database and backup unchanged until recovery is confirmed. There is no destructive restore endpoint or automatic replacement of live data. Regression tests compare recovered records and links, check backup isolation after later edits and reject existing output paths or mismatched models.

## Filtered application analytics

Generated workspaces display matching, open and completed record counts and a completion progress indicator. Integer fields show totals and averages; choice fields show counts for every configured option; links show how many matching records have a target. Free-text fields are not aggregated. All figures are computed server-side from the same bounded, filtered record list returned by the existing session-protected API. Empty results have no completion percentage or average. Analytics update on create, edit, complete, delete and filter operations. No tracking, network analytics service, chart dependency or new database tables are required. The automated tests exercise both summary calculations and the exported browser UI. The summaries describe the displayed dataset, not necessarily the full database.
